# 決定事項・未決定事項ログ

このファイルはユーザーとClaudeの両方が直接編集してよい「相談メモ」です。
決まったら「確定事項」に、まだ話し合い中のものは「未確定・要相談」に置く。
世界観の原本は [game_design.md](game_design.md) を参照。

## 確定事項

- 2026-09-24: MVPの範囲は「1晩分(複数の客が来店 + その晩の上納金の支払い判定まで)」を
  通しで作る。1人の客だけの縦串ではなく、ローテーションと上納金システムまで含める。
- 2026-09-24: 客・商品・会話などの具体的な中身(セリフ、キャラ設定)は、ユーザーと
  Claudeが一緒に相談しながらClaudeが下書きする方式で進める。
- 2026-09-24: 技術スタックは React + Vite + Zustand に決定。
- 2026-09-24: 画面UIの方向性は "That's Not My Neighbor" 風。中央に背景+人(客)+店枠
  (カウンター)のシーン。商品を見せられたら商品にフォーカスが寄り、背景が薄暗くなる。
  周囲に3つの情報パネルを置く:
  - **資料**: 事前に知っている静的な知識(紋章の意味、犯罪の証拠になりうる特徴の一覧、
    教会のガイドラインなど)。ゲーム内でずっと参照できる。
  - **まとめた情報**: その夜の会話で得た情報のログ(他の客から聞いた噂・証言など)。
    プレイ中に蓄積されていく。
  - **見た情報**: 今目の前の客/商品を調べて分かったこと(刃こぼれ・宝石の有無・
    値札・魂反応など)。客が変わるとリセットされる。
- 2026-09-24: 客・商品のビジュアルは今は仮素材(プレースホルダー)で作り、イラストは
  後で差し替える前提で進める。
- 2026-09-24: MVP時点で主人公は魂判別機を持たせる(判別機没収後の「共鳴」展開は
  MVPの先の拡張として後回し)。
- 2026-09-24: その晩の上納金を払えなかった場合、MVPでもゲームオーバー画面を出す
  (企画書通りの緊張感をそのまま実装する)。
- 2026-09-24: 経済モデルを「買取=即収入」から「仕入れ(支払い)→在庫→夜の終わりに
  査定して売る(収入)」の2段階に変更。買取時は3択(言い値で買う/値切る/断る)にし、
  値切りへの反応(あっさり応じる=後ろめたい/突っぱねる=正直)を「見た情報」に
  手がかりとして残す設計にした(ユーザー提案)。
- 2026-09-24: 売る側(査定)も買う側と対称的な3択にした(ユーザー提案)。
  「言い値で売る/高く売れないか粘る/やめておく」。粘って高値を狙えるのは普通の品
  だけで、魂入りなど危ない品を欲張ると買い手が取引そのものから手を引いてしまい
  0Gになるリスクがある(現状は確率でなく決定的な挙動。ランダム性を入れるかは
  今後の検討事項)。
- 2026-09-24: 査定(売り)画面も買いと完全に同じUI(資料/まとめた情報/見た情報+
  会話+判断)にした。仕入れた品ごとに「買い手」(仲買人)が設定されていて、話しかけ
  たり様子を観察できる。1人目の客(ダロン)の噂(東門の騎士増員)と、護符の買い手
  (フード姿の男)が「東門から運び出す」と話す内容が「まとめた情報」上で並んで
  見えるようにし、買い側と売り側をまたいだ情報の組み合わせが最初から機能する
  ようにした。買い手にもこの先(通報・値切り拒否など)ゲーム要素を足していく前提。
  データ構造: `CUSTOMERS[].item.buyer` に客と1対1で買い手を持たせ、仕入れ時に
  在庫へ丸ごと引き継ぐ(`src/store/gameStore.js` の itemToInventory)。
- 2026-09-24: イラスト実装後に使う「見た目だけで気づける手がかり」の受け皿を用意
  (ユーザー要望)。客・買い手データに `illustrationClues: []`(今は空、
  `{id,x,y,label,text}` 形式でイラスト上のホットスポット位置を%指定する想定)を
  追加。`ScenePanel` が中身のあるilustrationCluesを自動でクリック可能なホットスポット
  として表示し、クリックで「見た情報」に追加される(`inspectIllustrationClue`)。
  イラストが無い間は空配列なので見た目に変化なし。イラストができたら
  `scene-figure` を画像に差し替え、各キャラのillustrationCluesを埋めるだけで動く。
- 2026-09-24: 客・買い手の発言を、キャラクターの下あたりに吹き出しで表示するように
  した(ユーザー要望)。直近の発言(ナレーション以外)を`ScenePanel`内の
  `SpeechBubble`が自動表示。下のテキストログ(スクロールで全履歴を追える)は
  そのまま残している。商品にフォーカスが寄っている間は吹き出しも一緒に薄くなる。

## 方針転換: ストーリーはおまけ要素(2026-09-25)

ユーザーから「ストーリーはほとんどおまけ要素、世界観を守るための定規」「キャラに
設定もりもりにして毎回意味深なことを言われてもノイズ」との指摘。これを受けて:

- ストーリー(旧魂坑事故・黒幕「教授」)は掘り下げ優先度を下げ、worldbuilding.md/
  characters.mdの該当部分を「背景の存在・おまけ要素」に整理し直した。
- 代わりに、難易度曲線を**ゲーム的な判断の複雑さ**(情報量/板挟みになる利害関係/
  失敗の重さ)で作る方針を [story_outline.md](memory/story_outline.md) にまとめた
  (序盤=単一情報源・利害関係なし・ミスが軽い、終盤=複数情報の照合・教会と夜市の
  板挟み・ミスが重い)。
- story_outline.md / characters.md に、序盤〜終盤のキャラ・イベント案を9割程度
  下書きした。残り1割(再登場のトリガー条件、フラグの数値設計、終盤客の具体的な
  セリフなど)は実装しながら詰める。
- この方針はClaude側の永続メモリにも「feedback_yoiti_story_design」として保存済み
  (このプロジェクト外、Claudeの記憶フォルダ側の話なのでリンクなし)。

## 確定: UI/UX改善(2026-09-25)

ユーザーから3点指摘があり、うち1点を実装済み、2点は設計を記録した。

- **判断の結果を全画面ポップアップで隠さない(実装済み)**: 「値段ボタンを押したら
  反応を見ずに即決してしまう」との指摘。判断の結果(セリフ・増減額)を、画面全体を
  覆うモーダルではなく、キャラと吹き出しを残したまま会話エリア内にインライン表示
  するように変更した。`ResultPanel`(`src/components/panels.jsx`)。あわせて
  `SpeechBubble` がナレーション行も表示するようにし(以前は台詞のみ表示)、
  取引の結果テキストも会話ログ/吹き出しに流れるようにした
  (`src/store/gameStore.js` の各アクションが`dialogueLog`に結果を積むように変更)。
- **客数が実質倍になる問題(要調整)**: Day構成の「客数」は売りに来る客の数で、
  買い取った分だけ査定(売り)の客も追加で発生するため、実際の対話数は最大で
  表の2倍になる。story_outline.mdの表の客数を下方修正するか、査定側に「まとめて
  売る」のような時短手段を残すか、要検討(未着手)。
- **売らなかったアイテムの保存 → 実装・動作確認済み(2026-09-25)**。在庫
  (`inventory`)は週を通して持ち越すようにし、査定は「その日の在庫スナップショット」
  (`appraisalQueue`)に対して行うようにした。売れた品だけ`invId`で在庫から除去し、
  「やめておく」・魂入り品で買い手に逃げられた品は在庫に残る → 翌日以降の査定で
  また出てくる。これにより「客数が実質倍」問題も、査定をその日に全部やりきる
  必要がなくなったことで実質的に解消した(先送りが可能になったため)。
  ブラウザで、Day1で全品「やめておく」→Day2の査定にDay1分+Day2新規分が両方
  出てくることを確認済み。

## 確定: 心証・エンディング分岐(2026-09-25)

- `churchFavor`(教会)・`marketFavor`(夜市)という2つの隠しパラメータを追加。
  プレイ中は画面に一切表示しない(「正解」を数値で見せると企画書の方針に反するため)。
- 意味のある選択にだけ`favor: {church, market}`を仕込む形にした(すべての取引を
  評価対象にすると重くなるため): 各客の`resolution.buyFull/refuse/report`に
  任意で`favor`フィールドを持たせ、ストアが汎用的に加算する(`applyFavor`)。
  - 通報全般: 基本的に夜市側の得点(市場の秩序を守った、という扱い)
  - シスター・マレンとの取引: 買う→教会+8/断る→教会-3
  - 元締めヴィクターの裏取引: 受ける→夜市+12・教会-6/断る→夜市-4
- 7日目クリア時、心証と最終所持金から4種類のエンディングに分岐
  (`determineEnding`): 教会寄り/夜市寄り/大金持ち(所持金200G以上)/中立。
  「正解」を示すものではなく選択の結果をひとことで見せるだけ。
- ブラウザでの検証で、4エンディングすべての判定、マレン/ヴィクター取引による
  心証の加算が意図通り動くことを確認済み。

## 確定: ゲーム期間とDay構成(2026-09-25)

- ゲーム期間は**7日間**。7日目を乗り切ったらエンディング。
- Day1: 客3人(ダロン/イレア/ノア)、上納金60G、判別機あり。チュートリアル兼、
  魂の存在を初めて知る日。「魂入り1個+怪しい客1人+残りは普通」の比率(既存実装
  そのまま使う)。
- Day2から本格的に始まる。客数・上納金が徐々に増えていく。
- Day3は**必ず上納金を払えなくなる強制イベントの日**。その日の売上を夜の終わりに
  強盗(仮)でまるごと奪われる形にし、プレイヤーの実力に関係なく確実に発生させる。
  ゲームオーバーにはせず、元締めヴィクターが判別機を回収する一回限りの分岐にする。
- Day4から判別機なし。代わりに「共鳴」で商品を調べると自動的に魂反応がわかる
  ようになる(企画書9章の演出)。
- 客数・上納金の具体的な数値は [story_outline.md](memory/story_outline.md) の表に
  仮置きした。プレイして調整する前提。
- 実装が必要になる大きな変更: 日をまたぐループ(Day管理)、所持金・まとめた情報を
  週を通して持ち越す仕組み、Day3強制イベント、Day4判別機喪失/共鳴演出。
  → **実装・動作確認済み(2026-09-25)**。詳細はDEVELOPMENT_LOG.mdを参照。
  → **Day2〜7の客の本文も書き上げ済み(2026-09-25)**。story_outline.md/
  characters.mdのキャラ案(気弱な老人、図々しい行商人、シスター・マレン、
  元締めヴィクター、ダロン再登場など)を反映した。頭数合わせの軽いモブだけ
  機械生成のfillerCustomerを使用。ブラウザでの自動プレイで7日間クリアまで
  破綻なく動くことを確認済み。
  → **教会/夜市の心証システムとエンディング分岐も実装済み(2026-09-25)**。
  詳細は下記「確定: 心証・エンディング分岐」を参照。

  今回は直近のフィードバックを優先する方針。
  棚の在庫ツールチップに「鑑定済み: X/Y」を追加する一方、レビュー指摘に
